# Plan Evidence-Based Marketing

1. Run the Repository Intelligence Gate and record READY or DEGRADED evidence.
2. Use `marketing-growth-website` in `discover` mode and complete `.ai/templates/marketing-context.yaml`.
3. Build `.ai/templates/marketing-claim-ledger.yaml`. Separate verified public proof, assumptions, unknowns, and rejected claims.
4. Map audience, problem, funnel stage, traffic source, source promise, page goal, proof, CTA, and next state.
5. Use `marketing-growth-website` in `plan` mode and complete `.ai/templates/marketing-brief.md`.
6. Compose `seo-geo-website`, `design-taste-website`, and `animation-design-engineering` when applicable. Reconcile discovery, message meaning, responsive design, accessibility, performance, privacy, localization, and static fallbacks.
7. Complete `.ai/templates/marketing-measurement-plan.yaml` before adding or changing instrumentation. When an experiment is justified, use `marketing-growth-website` in `experiment` mode and complete `.ai/templates/marketing-experiment.md` before exposure.
8. Select `.ai/quality-profiles/marketing-growth.yaml` plus applicable web, SEO/GEO, visual, animation, security, privacy, accessibility, and performance profiles.
9. Stop for explicit implementation approval before editing existing application files.
10. Implement only approved scope. Treat pixels, production analytics, personalization, external publishing, outbound messages, account mutations, experiment launch, and budget spend as separately protected actions.
11. Validate source/build output, representative journeys, message match, claim provenance, CTA consequence, analytics semantics, consent, data minimization, accessibility, performance, SEO/GEO, localization, and rollback.
12. Complete `.ai/templates/marketing-review.md`. Report outcomes as `MEASURED`, `INCONCLUSIVE`, `INVALID`, or `NOT_MEASURED`; never infer success from missing evidence.
