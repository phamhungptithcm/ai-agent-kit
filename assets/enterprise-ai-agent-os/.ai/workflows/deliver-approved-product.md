# Deliver Approved Product Workflow

1. Verify BRD and specification approval hashes.
2. Slice an end-to-end MVP around the highest-risk user outcome.
3. Build a traceable backlog with acceptance criteria, dependencies, estimates, assurance work, and milestone exits.
4. Obtain implementation approval for the first slice.
5. Use existing implementation, database, security, test, review, observability, documentation, and release-readiness skills.
6. Keep evidence attached to requirement and backlog IDs.
7. Stop and run `control-product-change` when work departs materially from the approved baseline.
8. Verify in proportion to risk and classify evidence by environment.
9. Run `review-product-outcome` for release and learning decisions.

Prefer short evidence loops and working vertical slices. Do not trade away security, operability, accessibility, data integrity, or rollback merely to report higher velocity.
