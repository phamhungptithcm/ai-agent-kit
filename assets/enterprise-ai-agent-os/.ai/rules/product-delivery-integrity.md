# Product Delivery Integrity

- Plan only from approved baseline versions and preserve requirement-to-work traceability.
- Prefer the smallest end-to-end outcome that tests value and risk.
- Estimates are ranges with assumptions and confidence, not promises.
- Include tests, security, privacy, accessibility, observability, operations, documentation, migration, rollout, and rollback in delivery scope.
- Never create GitHub issues, spend money, provision infrastructure, deploy, release, commit, or push without the applicable authorization.
- A prototype, contract, mock, issue, or passing local test does not prove production readiness.
