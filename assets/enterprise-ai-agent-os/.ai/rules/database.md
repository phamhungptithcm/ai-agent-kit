# Database Rules

required_review:
  - "Do not call `repository.save()` inside large loops."
  - "Use batch update or bulk persistence for large transactions."
  - "Avoid SELECT * in production queries; retrieve only required columns."
  - "Use parameterized queries or prepared statements; never build SQL through string concatenation."
  - "Always specify deterministic ORDER BY when result order matters."
  - "Use pagination or bounded result sets for user-facing, reporting, and search queries."
  - "Review execution plans for new or materially changed queries."
  - "Review index usage; avoid unnecessary full table scans, index scans on low-selectivity columns, and missing composite indexes."
  - "Review join order, join cardinality, and predicate selectivity for large datasets."
  - "Avoid N+1 query patterns in ORM and application code."
  - "Fetch only required data; avoid unnecessary eager loading and oversized object graphs."
  - "Use projections or DTOs instead of loading entire entities when appropriate."
  - "Prefer set-based SQL operations over row-by-row processing."
  - "Avoid repository.save() or equivalent persistence operations inside large loops."
  - "Use batch insert/update/delete for bulk operations."
  - "If row-by-row persistence is unavoidable, document transaction size, batch size, flush/clear behavior, locking risk, retry strategy, idempotency, and approval evidence."
  - "Choose appropriate transaction boundaries; keep transactions as short as possible."
  - "Review isolation level, locking behavior, optimistic/pessimistic locking, and deadlock risk."
  - "Review concurrent update scenarios and lost-update protection."
  - "Review cascading updates/deletes and referential integrity impacts."
  - "Review foreign keys, unique constraints, check constraints, and NOT NULL constraints."
  - "Validate data consistency before and after migrations."
  - "Design schema migrations to be backward compatible for rolling or zero-downtime deployments."
  - "Separate additive schema changes from destructive cleanup."
  - "Delay dropping columns, tables, indexes, or constraints until all consumers are migrated."
  - "Provide rollback or forward-fix strategy for every schema migration."
  - "Validate migration performance on production-scale datasets."
  - "Review migration locking duration and online DDL capabilities."
  - "Coordinate schema changes with existing CI/CD database migration pipelines (Flyway, Liquibase, Jenkins, GitLab, etc.)."
  - "Never execute production data fixes autonomously."
  - "Require business approval, backup strategy, validation queries, and rollback plan before production data corrections."
  - "Treat financial, payment, ledger, reconciliation, audit, compliance, regulated, and PII data as High or Critical risk until explicitly classified otherwise."
  - "Protect sensitive data through encryption, masking, row-level security, and least-privilege access where applicable."
  - "Review partitioning, sharding, archival, and retention impacts for large tables."
  - "Review replication, CDC, materialized views, cache invalidation, and downstream synchronization impacts."
  - "Review database resource usage including CPU, memory, temp space, IO, connection pool utilization, and transaction log growth."
  - "Ensure audit fields (created_by, created_at, updated_by, updated_at) remain consistent where required."
  - "Document any consumer-visible schema or data behavior changes."
high_risk_operations:
  - "DELETE or UPDATE without WHERE is prohibited unless explicitly approved."
  - "DROP/TRUNCATE operations require explicit approval."
  - "Large UPDATE/DELETE statements should execute in controlled batches."
  - "Validate affected row counts before committing."
  - "Verify backup or recovery strategy before destructive operations."
  - "Never disable constraints or triggers without documented approval."
  - "Avoid long-running transactions that block production workloads."
  - "Avoid schema changes during peak traffic unless explicitly planned."
orm_review:
  - "Review lazy/eager loading behavior."
  - "Prevent N+1 queries."
  - "Avoid unnecessary entity loading."
  - "Use bulk update/delete instead of iterating entities."
  - "Avoid excessive flush() operations."
  - "Clear persistence context during large batches."
