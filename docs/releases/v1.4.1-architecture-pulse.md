# v1.4.1 — Architecture Pulse That Understands Change

## Release story

### A stable score can still hide a new architecture problem

Architecture Pulse v1.4.0 made repository structure visible to AI coding agents. It could identify dependency cycles, boundary violations, graph depth, hotspots, cohesion, and blast radius, then compare those signals with a trusted baseline.

That foundation exposed an important limitation: aggregate counts are not finding identity.

If an old dependency cycle was fixed and a different cycle appeared, both snapshots could still report one cycle. The total looked stable even though the architecture had changed in a meaningful way. Coverage could also look stronger than the source evidence behind it, especially when unsupported files and external dependencies were grouped too broadly.

v1.4.1 addresses those trust gaps.

Architecture Pulse now gives every actionable finding a stable fingerprint. A comparison reports what is new, fixed, unchanged, or updated. Base/head analysis shows changed edges, affected components, and witness paths that explain why a file or component is in the impact set.

Evidence quality is now part of the decision. Pulse distinguishes source fallback, AST-verified, resolver-verified, and explicit manifest evidence, while reserving an index-verified tier for a future trusted adapter. A blocking rule cannot silently rely on evidence below the team's approved precision tier. It returns DEGRADED so a person or agent knows that stronger analysis is required.

Coverage is equally explicit. Supported source, policy exclusions, declared external packages, unresolved internal imports, ambiguity, and parse failures remain separate. An unsupported source file cannot disappear behind a 100% label.

This release also adds bounded graph shards, an opt-in non-authoritative diagnostic cache, expiring integrity-bound waivers, SARIF export, append-only trends, and a checked-in polyglot benchmark with measurable precision and recall.

v1.4.1 also includes the Product Language Gate developed in parallel. When an agent changes labels, controls, messages, accessibility text, or displayed-data meaning, the gate requires natural, concise, context-correct language and evidence from the real interface state. It is designed to reduce robotic UI copy without inventing product behavior or business meaning.

The purpose of v1.4.1 is not to make the Pulse score more impressive. It is to make architectural evidence harder to misread and more useful during real agent work.

## Release notes

### Highlights

- Added stable fingerprints for graph edges, cycles, boundaries, layer-order violations, and public-API bypasses.
- Added exact new, unchanged, updated, and fixed finding states, preventing new debt from canceling fixed debt in aggregate counts.
- Added truthful coverage categories for supported source, unsupported source, policy exclusions, external packages, unresolved internal imports, ambiguity, and parse failures.
- Split analysis compatibility from policy configuration so rule changes do not erase architectural history.
- Based baseline compatibility on graph, metric, extractor, and resolver semantics; the package version is retained as provenance.
- Added explicit v1 baseline inspection and migration preview. v1 evidence cannot be compared silently with v2.
- Added evidence tiers and resolver provenance for comment-aware JavaScript/TypeScript, tsconfig and workspace paths, Python AST, Go modules, Cargo workspaces, JVM packages, C# namespaces, and explicit cross-language bridges.
- Added a typed, component-aware file graph with layer and public-API rules.
- Added pulse diff for Git base/head and working-tree analysis, including changed edges, affected components, and witness paths.
- Added forbidden, required, transitive, layer-order, public-API, and no-new-finding policies.
- Added exact, integrity-bound, expiring waivers that fail closed when invalid or expired.
- Added pulse doctor, policy validation, baseline inspection, migration preview, richer explain output, SARIF 2.1.0, and hash-chained local trends.
- Added an opt-in content-addressed diagnostic cache. Cache hits are DEGRADED and governed baseline, check, and diff paths always analyze fresh source; stale or tampered entries are ignored and recomputed.
- Added one end-to-end deadline and bounded graph, inventory, and diagnostic evidence shards.
- Added a seven-language golden graph and mutation gates through npm run eval:pulse.
- Added the Product Language Gate for natural, concise, accessible, and context-correct UI content and displayed-data semantics.

### Try it locally

~~~bash
npm install -g @hunpeolabs/ai-agent-kit@1.4.1

ai-agent-kit pulse doctor
ai-agent-kit pulse diff --base origin/main --head working-tree --format text
ai-agent-kit pulse scan --output .ai-agent-kit/pulse/results/latest.json
ai-agent-kit pulse explain --file .ai-agent-kit/pulse/results/latest.json
~~~

Create a reviewed v2 baseline only after representative results have been inspected:

~~~bash
ai-agent-kit pulse baseline create --config pulse.json
ai-agent-kit pulse check --config pulse.json --format text
~~~

### Security and trust

- Analysis remains repository-local, offline by default, and free of telemetry.
- Optional analyzers use fixed read-only commands, bounded output, and no implicit downloads.
- CI can verify a baseline but cannot create one.
- Existing trusted baseline files cannot be overwritten silently; advancing history requires a new reviewed baseline name.
- Invalid, expired, future-dated, or tampered waivers fail closed.
- Low-precision blocking matches return DEGRADED instead of passing or blocking with unsupported confidence.
- Source, analysis configuration, policy, repository state, semantic versions, graph evidence, and artifacts have separate integrity bindings.
- Task reports and Change Passports continue to reject stale, foreign, tampered, or incorrectly bound evidence.
- The aggregate Pulse index remains diagnostic and has no standalone authority.

### Upgrade notes

- New scans use the Architecture Pulse v2 result and baseline contracts.
- Existing v1 results remain readable for integrity and freshness checks.
- Existing v1 baselines require pulse baseline migrate --dry-run followed by a reviewed fresh v2 baseline.
- Configuration without schema_version keeps the v1 blocking-tier default for compatibility. New policy should set schema_version to 2 and choose blocking_minimum_tier explicitly.
- Policy-only changes no longer force a baseline reset. Analysis configuration changes still require a reviewed baseline.

### Effectiveness evidence

The checked-in benchmark reports explicit denominators for dependency-edge precision and recall across seven language fixtures. It also verifies deterministic digests, seeded blocking-finding detection, and truthful unsupported-scope behavior.

These fixtures are release evidence, not a universal accuracy claim. Teams should calibrate blocking rules, resolver availability, false-block rates, and performance against representative repositories before expanding enforcement.

### Known limitations

- Static analysis cannot prove every dynamic import, reflection target, generated binding, framework convention, runtime route, service call, event, or data dependency.
- Some ecosystems use source or manifest fallback when a native resolver is unavailable.
- Large graphs use bounded blast-radius sampling and return DEGRADED.
- SARIF exposes structural findings; it does not turn Pulse into a security scanner.
- A passing Pulse policy does not prove security, runtime reliability, maintainability, accessibility, or production readiness.
- Product Language Gate evidence still requires review in the rendered interface; string-file-only checks are not sufficient.
- No hosted scanning, telemetry, automatic architecture rewrite, implicit analyzer installation, Sentrux dependency, or Sentrux compatibility layer is included.
