# v1.3.0 — Governed Shared Memory

## Câu chuyện ra mắt

### AI agents không chỉ cần nhớ — chúng cần biết điều gì đáng được nhớ

Khi một AI agent làm việc một mình trong một phiên ngắn, “memory” thường chỉ
có nghĩa là tiếp tục cuộc trò chuyện. Nhưng khi có nhiều subagent, nhiều phiên,
nhiều worktree và nhiều máy cùng tham gia, cách hiểu đó nhanh chóng trở nên
nguy hiểm.

Nếu mọi agent cùng ghi vào một bộ nhớ chung không giới hạn, hệ thống có thể giữ
lại một kết luận đã lỗi thời, đưa dữ liệu nhạy cảm sang sai phạm vi, hoặc biến
một hướng dẫn độc hại thành “kiến thức” được dùng lại ở những lần sau.

Vì vậy mục tiêu của v1.3.0 không phải là tạo ra một bộ nhớ lớn hơn.

**Mục tiêu là tạo ra một bộ nhớ có thể kiểm chứng, kiểm soát và thu hồi.**

Phiên bản này tách rõ bốn thứ vốn thường bị trộn lẫn: policy bắt buộc trong
repository, trạng thái cuộc trò chuyện do host quản lý, context tạm thời của
team trong một task, và kiến thức bền vững đã được duyệt.

Subagent có thể đề xuất một điều đáng nhớ, nhưng không thể tự phê duyệt. Mỗi đề
xuất phải gắn với task, assignment, source commit, evidence và handoff hiện tại.
Team Lead kiểm tra; một Memory Approver độc lập mới có quyền promotion. Nếu các
agent bất đồng, memory bị chặn thay vì lấy biểu quyết đa số làm sự thật.

Một session mới chỉ nhận tối đa một nhóm nhỏ memory phù hợp với repository,
scope, ACL, lifecycle và token budget. Receipt giải thích item nào được chọn,
item nào bị loại và vì sao — không lưu prompt, cuộc trò chuyện hay suy luận ẩn.

Local SQLite vẫn là mặc định để dự án hoạt động không cần dịch vụ mạng. Chia sẻ
qua worktree hoặc host khác là opt-in, có repository binding, chữ ký, expiry,
replay protection và authorization riêng. Khi remote lỗi, hệ thống nói rõ
`DEGRADED`; nó không âm thầm hạ chuẩn tin cậy.

v1.3.0 dành cho các team đã bắt đầu dùng nhiều coding agent hoặc subagent và
muốn giữ lại kiến thức hữu ích qua nhiều phiên, nhưng vẫn cần biết kiến thức đó
đến từ đâu, ai duyệt, còn hiệu lực không và có thể thu hồi bằng cách nào.

## Release notes

### Highlights

- Added the canonical `memory-entry-v3` contract across runtime, CLI, policy,
  YAML template, JSON Schema, Team Context, and documentation.
- Added a model-independent `MemoryStore` interface and transactional
  `LocalSqliteMemoryStore` with WAL, optimistic revisions, deterministic JSONL
  interchange, integrity health, idempotent receipts, and bounded busy retry.
- Added evidence-bound subagent `memory_candidates`, Team Lead review,
  deterministic deduplication/conflict blocking, and independent promotion.
- Added scoped cross-session retrieval with hard filters before keyword or
  optional semantic ranking, a five-entry default, token budgets, and
  privacy-safe context receipts.
- Added signed repository-bound memory packs, replay protection, remote adapter
  capability negotiation, explicit remote-write authorization, and honest
  local fallback.
- Added previewable v2 JSONL migration, content-identical backups,
  conflict-safe apply, unchanged-revision rollback, adversarial tests, an
  offline memory benchmark contract, threat model, and incident guidance.

### Security and privacy

- Subagents cannot create approved memory or self-approve candidates.
- Raw prompts, chat history, chain-of-thought, credentials, secrets, source
  bodies, raw tool output, sensitive logs, PII, regulated data, and production
  customer data are denied durable fields.
- Organization/repository identity, lifecycle, ACL, scope, conflict, and source
  reachability filters run before relevance ranking.
- Unsigned, foreign, expired, tampered, replayed, or incompatible packs fail
  closed. Remote capability claims must be verified by the adapter contract.

### Migration

Preview before applying:

```bash
npx --yes @hunpeolabs/ai-agent-kit@1.3.0 update --dry-run
ai-agent-kit runtime memory migrate
```

Apply only after reviewing every `create`, `update`, `preserve`, `reject`, and
`conflict` result:

```bash
ai-agent-kit runtime memory migrate --apply
```

Run migration only after previewing the plan and reviewing every reported
change, rejection, and conflict.

### Known limitations

- No hosted remote memory service ships in the package; only the verified
  adapter boundary and safe local fallback are included.
- HMAC pack keys require external distribution/rotation.
- Built-in scanning is not a replacement for organizational DLP, privacy,
  legal, or compliance review.
- Local/synthetic evidence does not prove a third-party backend or production
  operating environment.
