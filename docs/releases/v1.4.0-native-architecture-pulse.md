# v1.4.0 — Native Architecture Pulse

## Câu chuyện ra mắt

### Code có thể chạy đúng hôm nay, nhưng kiến trúc có đang âm thầm xấu đi?

Một pull request có thể vượt qua test, lint và review nhưng vẫn tạo thêm một
vòng phụ thuộc, kéo domain logic sang UI, làm một module trở thành điểm nghẽn,
hoặc mở rộng phạm vi ảnh hưởng của lần thay đổi tiếp theo.

Những thay đổi ấy hiếm khi làm build đỏ ngay lập tức. Chúng tích tụ chậm, cho
đến khi team mất nhiều thời gian hơn để hiểu code, sửa một chỗ lại vỡ nhiều
chỗ, và mỗi agent phải đọc ngày càng nhiều context trước khi dám hành động.

Vì vậy v1.4.0 đưa **Native Architecture Pulse** vào AI Agent Kit.

Mục tiêu của phiên bản này không phải là cho kiến trúc một điểm số đẹp. Mục
tiêu là biến cấu trúc repository thành bằng chứng có thể đọc, so sánh và kiểm
chứng: dependency graph nào được tìm thấy, cycle nào xuất hiện, boundary nào bị
vượt qua, độ sâu thay đổi ra sao, hotspot nằm ở đâu, và file nào có nhiều code
phụ thuộc vào nó.

Pulse chạy local-first và offline. Nó dùng inventory từ Git, từ chối symlink và
hard link không an toàn, giới hạn số file, byte và thời gian, rồi trích xuất
dependency một cách bảo thủ cho JavaScript/TypeScript, Python, Go, Rust,
Java/Kotlin và C#. Cross-language edge chỉ tồn tại khi team khai báo bridge rõ
ràng; điều không chắc chắn được giữ lại dưới dạng unresolved evidence thay vì
được đoán thành sự thật.

Baseline được gắn với repository, cấu hình, phiên bản analyzer và digest. Một
baseline bị sửa, lấy từ repository khác, dùng cấu hình cũ hoặc dựa trên evidence
không đầy đủ sẽ fail closed. Pulse index chỉ để chẩn đoán; chỉ những rule có tên,
threshold và severity do team chọn mới được quyền block workflow.

Kết quả có thể gắn với task report và Change Passport, nhưng không thay thế
review, approval hay quyền quyết định của con người. Nó bổ sung một câu trả lời
có bằng chứng cho câu hỏi mà coding agent thường bỏ sót: **thay đổi này có làm
hệ thống khó thay đổi hơn vào ngày mai không?**

Architecture Pulse là module clean-room, first-party của AI Agent Kit. Package
không chứa code, dependency, binary, service, telemetry, asset hay runtime của
Sentrux.

v1.4.0 dành cho các team dùng AI coding agents trên codebase đang phát triển và
muốn kiểm soát architecture drift sớm, ngay trong repository, mà không phải gửi
source code sang một dịch vụ phân tích bên ngoài.

## Release notes

### Highlights

- Added deterministic Git-aware repository inventory with containment,
  symlink/hard-link refusal, generated/vendor filtering, and hard file, byte,
  candidate, and time limits.
- Added conservative dependency extraction for JavaScript/TypeScript, Python,
  Go, Rust, Java/Kotlin, and C#, plus explicit manifest-only cross-language
  bridges and visible unresolved evidence.
- Added dependency graph evidence for cycles, condensation depth across every
  root, module cohesion, configured boundaries, fan-in/fan-out hotspots, and
  bounded reachable-dependent blast radius.
- Added repository-bound, tamper-evident baselines with source/config digests,
  tool/extractor/metric versions, optional governance provenance, and
  fail-closed foreign, stale, incompatible, or degraded outcomes.
- Added explicit regression policy for cycles, boundaries, depth, cohesion,
  hotspots, blast radius, coverage, and confidence. The aggregate Pulse index
  remains diagnostic and has no standalone blocking authority.
- Added `pulse scan`, `pulse baseline create|verify`, `pulse check`, and
  `pulse explain`, with stable JSON, concise text, task-bound artifacts, and
  distinct exit codes for normal, blocking, and untrusted/degraded outcomes.
- Added digest-valid Architecture Pulse evidence to final task reports and
  optional Change Passport assurance.
- Added canonical schemas, packed-package coverage, adversarial filesystem
  tests, baseline trust tests, large-graph bounds, and clean-room documentation.

### Try it locally

```bash
ai-agent-kit pulse scan --format text
ai-agent-kit pulse baseline create --config pulse.json
ai-agent-kit pulse check --config pulse.json --format text
```

Start without blocking rules. Review representative results, choose boundaries
and thresholds with the team, then create the baseline that future changes will
compare against.

### Security and trust

- Analysis stays repository-local and does not require network access or
  telemetry.
- Inputs and artifacts must remain inside the repository; linked or oversized
  files fail closed or reduce evidence quality visibly.
- Baseline integrity and repository/config/version bindings are verified before
  comparison.
- `DEGRADED`, `STALE`, and `UNTRUSTED` are non-passing evidence states.
- Task reports and Change Passports reject tampered or foreign task bindings.
- Task reports and Change Passports mark previously valid Pulse evidence stale
  after the repository commit or worktree changes.

### Known limitations

- Extraction is intentionally conservative and is not a compiler, language
  server, runtime tracer, or universal semantic model.
- Dynamic imports, reflection, generated runtime wiring, framework magic, and
  external services may remain unresolved.
- Blast radius is exact through 2,000 graph nodes; larger graphs use a visible,
  deterministic 200-node sample and return `DEGRADED`.
- Metrics describe the extracted graph. They do not prove runtime reliability,
  security, maintainability, or production readiness.
- No hosted scanning, telemetry, automatic architecture rewrite, or Sentrux
  compatibility layer ships in v1.4.0.
