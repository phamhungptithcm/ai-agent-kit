> Release scope based on the released `v1.6.0` tag. Local, GitHub, registry,

> be verified against its exact merge commit and package provenance.

## What changes

Users can describe a new product naturally. The Conversation Entry Gate detects
greenfield intent before Repository Intelligence, selects `run-product-genesis`,
and resumes one active Product Workspace in later sessions. The user no longer
needs to mention Product Genesis, v1.6, or a stage skill.

The detector is local and deterministic. It combines versioned Vietnamese and
English signal groups with bounded workspace state and returns reason codes
without repeating the raw request or adding it to routing evidence. Existing
task and Product Workspace records retain their separately governed goal or idea
fields. Multiple active products, conflicting signals, or invalid workspace
state require confirmation or repair instead of silent choice.

## Safety and compatibility

- Existing Product Genesis artifacts, successor history, stage controller,
  exact-hash approvals, convergence, evidence, and release gates are unchanged.
- Existing-system bug, feature, review, and engineering workflows remain routed
  through their current paths.
- Governed task creation records the detector/config hash, reason codes, entry
  action, and selected product ID without duplicating the request in routing
  evidence; the task's existing `goal` contract remains unchanged.
- The implementation adds no dependency, model call, hosted classifier, network
  requirement, or autonomous external write.
- Deterministic enforcement exists where AI Agent Kit owns task creation or a
  supported entry hook. Instruction-only hosts remain advisory.
